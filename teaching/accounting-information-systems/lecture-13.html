Microteach 13.1 · 1:14Types of audit

There are four main types.

Read the script

Not every auditor checks the financial statements. There are four main kinds of audit.

There are four main types. A financial audit checks whether the financial statements are fairly presented. An information systems audit reviews controls over the AIS. An operational audit evaluates efficiency and effectiveness. And a compliance audit checks whether laws and rules are followed.

Auditors can be internal, employed by the company and reporting to the audit committee, or external: an independent CPA firm giving an opinion to shareholders.

Today, information systems audit work is part of almost every financial audit, because the numbers come from the ERP.

All auditors share one principle: independence and objectivity. An audit is only as valuable as the auditor's independence.

So: financial, information systems, operational and compliance.

Quick check. An audit that evaluates efficiency and effectiveness is which type? Pause and pick.

An operational audit.

Microteach 13.2 · 1:11The risk-based audit approach

The risk-based audit approach has four steps: identify the threats, identify the controls that should prevent or detect them, evaluate those controls, and look for…

Read the script

Auditors can't check everything. So they start with what could go wrong.

The risk-based audit approach has four steps: identify the threats, identify the controls that should prevent or detect them, evaluate those controls, and look for compensating controls where there are weaknesses.

Evaluating a control has two parts. Design: would this control work if it operated as described? And operating effectiveness: does it actually work, consistently, all year?

Evidence comes from inquiry, asking people; observation, watching the control happen; inspection of documents and logs; and reperformance, doing the control yourself.

A compensating control offsets a weakness elsewhere. For example, there's no segregation of duties, but the owner reviews every payment.

So: start with the threats, find the controls, and test them.

Quick check. When the auditor performs the control themselves to test it, what's that called? Pause and pick.

Reperformance.

Microteach 13.3 · 1:08Auditing around, through and with the computer

Auditing around the computer compares inputs to outputs, and treats the processing as a black box.

Read the script

When the system does the processing, how does the auditor check it?

Auditing around the computer compares inputs to outputs, and treats the processing as a black box. It's simple, but it ignores how the system actually works.

Auditing through the computer tests the processing itself, to confirm the programs work as intended.

Tools include test data, feeding in fake transactions, valid and invalid, to see if they're handled correctly; an integrated test facility, a dummy entity inside the live system; and parallel simulation, rerunning real data through the auditor's own program.

Auditing with the computer means using software to do the audit work itself: extracting data, sampling, recalculating and analyzing.

So: around the computer, through the computer, and with the computer.

Quick check. Feeding fake transactions into a system to test its processing is called what? Pause and pick.

The test data technique.

Microteach 13.4 · 1:09CAATs and audit data analytics

CAATs are computer-assisted audit techniques: software that auditors use to analyze client data directly.

Read the script

Why test twenty-five invoices when you can test all two million?

CAATs are computer-assisted audit techniques: software that auditors use to analyze client data directly.

Common tools include IDEA, Diligent's analytics, formerly known as ACL, Excel with Power Query, and increasingly Python and SQL.

Typical tests: duplicate payments, gaps in invoice number sequences, Benford's law to spot unnatural number patterns, unusual journal entries, and vendors that match employees.

Benford's law says that in many real data sets, the leading digit is one about thirty percent of the time. Made-up numbers often don't follow that pattern.

The big benefit is testing the whole population, not just a sample, so you find the exceptions that sampling would miss.

So: test everything, then investigate the exceptions.

Quick check. Under Benford's law, which leading digit is most common? Pause and pick.

One.

Microteach 13.5 · 1:06Continuous auditing and monitoring

Continuous auditing uses technology to collect and analyze audit evidence as transactions happen, rather than months later.

Read the script

Why wait until year end to find a problem that happened in March?

Continuous auditing uses technology to collect and analyze audit evidence as transactions happen, rather than months later.

Continuous monitoring is management's version: automated checks that watch controls and transactions all the time.

Techniques include embedded audit modules built into the ERP, automated alerts when a rule is broken, dashboards of control test results, and snapshots that record transactions as they're processed.

Example. A payment over fifty thousand dollars is released without a second approval. The system sends an alert instantly, and it's investigated the same day, not at the year-end audit.

So: find it fast, and fix it fast.

Quick check. Audit code built inside the ERP to flag transactions is called what? Pause and pick.

An embedded audit module.

Microteach 13.6 · 1:20SOC 1 and SOC 2 reports

SOC reports, short for System and Organization Controls, are independent CPA reports on a service organization's controls, issued under AICPA standards.

Read the script

Your ERP might run in someone else's data center. How do you know their controls work?

SOC reports, short for System and Organization Controls, are independent CPA reports on a service organization's controls, issued under AICPA standards.

SOC one covers controls relevant to customers' financial reporting, like at a payroll processor. SOC two covers security, availability, processing integrity, confidentiality and privacy. SOC three is a short public version of SOC two.

Each comes in two types. Type one looks at control design at a point in time. Type two tests operating effectiveness over a period, usually six to twelve months. Auditors prefer type two.

Every SOC report lists complementary user entity controls: things your company must do for the provider's controls to work. Always read that section.

So: SOC one for financial reporting, and SOC two for security and trust.

Quick check. Which type of SOC report tests operating effectiveness over a period of time? Pause and pick.

Type two.
